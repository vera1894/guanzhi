## 🎯 部署目标

将 admin-web 前端部署到后端同一台服务器,实现:
- **访问地址**: `http://52.83.127.15/admin/` (或使用域名)
- **API调用**: 通过同源反向代理到 8085 端口,避免 CORS 问题
- **后端服务**: 无需修改,继续运行在 8085 端口

- [ ] 已安装或可以安装 Nginx
- [ ] 有服务器 root 或 sudo 权限

## 二、服务器端部署

### 2.1 创建部署目录

```bash
# 创建静态文件目录
sudo mkdir -p /var/www/guanzhi-admin-web

# 修改权限(根据实际用户调整)
sudo chown -R ec2-user:ec2-user /var/www/guanzhi-admin-web
```

### 2.2 上传构建产物

**方式一: 使用 SCP**

本地执行:
```bash
scp admin-web-dist.tar.gz ec2-user@52.83.127.15:/tmp/
```

**方式二: 使用 AWS SSM** (如果配置了 SSM)

本地执行:
```bash
aws s3 cp admin-web-dist.tar.gz s3://your-bucket/
```

服务器执行:
```bash
aws s3 cp s3://your-bucket/admin-web-dist.tar.gz /tmp/
```

### 2.3 解压到部署目录

服务器执行:
```bash
cd /var/www/guanzhi-admin-web

# 清空旧版本(首次部署可跳过)
rm -rf ./*

# 解压新版本
tar xzf /tmp/admin-web-dist.tar.gz --strip-components=1

# 验证文件
ls -la
# 应该看到 index.html, assets/, 等文件
```

## 三、Nginx 配置

### 3.1 安装 Nginx (如果未安装)

**Ubuntu/Debian**:
```bash
sudo apt update
sudo apt install -y nginx
sudo systemctl enable nginx
sudo systemctl start nginx
```

**CentOS/RHEL**:
```bash
sudo yum install -y nginx
sudo systemctl enable nginx
sudo systemctl start nginx
```

### 3.2 创建站点配置

创建配置文件:
```bash
sudo nano /etc/nginx/conf.d/guanzhi-admin.conf
```

配置内容:
```nginx
server {
    listen 80;
    server_name 52.83.127.15;  # 如果有域名,替换为域名

    # 后台前端静态文件
    location /admin/ {
        alias /var/www/guanzhi-admin-web/;
        try_files $uri $uri/ /admin/index.html;
        index index.html;
    }

    # 前端 API 请求反向代理到后端 8085
    location /api/ {
        proxy_pass http://127.0.0.1:8085/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # 超时设置
        proxy_connect_timeout 60s;
        proxy_send_timeout 60s;
        proxy_read_timeout 60s;
    }

    # Inspector API (如果路径不同可能需要单独配置)
    location /admin/inspector/ {
        proxy_pass http://127.0.0.1:8085/admin/inspector/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header Authorization $http_authorization;

        # 超时设置(Inspector查询可能较慢)
        proxy_connect_timeout 90s;
        proxy_send_timeout 90s;
        proxy_read_timeout 90s;
    }

    # 日志配置
    access_log /var/log/nginx/guanzhi-admin-access.log;
    error_log /var/log/nginx/guanzhi-admin-error.log;
}
```

**关键配置说明**:
- `alias /var/www/guanzhi-admin-web/`: 前端静态文件路径
- `try_files ... /admin/index.html`: 支持 Vue Router 的 history 模式
- `proxy_pass http://127.0.0.1:8085/`: 反向代理到后端
- `/api/` → 后端 `/` (自动去掉 `/api` 前缀)

### 3.3 检查并重载配置

```bash
# 检查配置语法
sudo nginx -t

# 如果提示 OK,重载配置
sudo systemctl reload nginx
```

## 四、验证部署

### 4.1 检查服务状态

```bash
# 检查 Nginx 状态
sudo systemctl status nginx

# 检查后端服务(8085)
lsof -i :8085
# 或
ps aux | grep "server.port=8085"
```

### 4.2 访问前端页面

浏览器打开: `http://52.83.127.15/admin/`

**预期结果**:
- 看到登录页面
- URL 地址栏显示 `/admin/`

**如果出现问题**:
- **404 Not Found**: 检查 Nginx 配置中的 `alias` 路径和 `try_files`
- **空白页**: F12 打开控制台查看错误,可能是静态资源路径问题
- **Connection Refused**: 检查 Nginx 是否正常运行

### 4.3 测试登录

1. 使用管理员账号登录:
   - **手机号**: `15810349766` + 短信验证码
   - **测试后门**: `admin` / `123456`

2. 打开浏览器开发者工具 (F12) → Network 标签

3. 登录成功后,检查请求:
   - URL 应该是: `http://52.83.127.15/api/user/checkCodeOrLogin`
   - 状态码: `200`
   - 响应包含 `token`

### 4.4 测试 Inspector 功能

登录成功后:

1. 访问用户详情查询: `/admin/#/inspector/user`
   - 输入用户ID: `11`
   - 点击查询
   - 检查 Network: `GET /api/admin/inspector/user/11`

2. 访问分享详情查询: `/admin/#/inspector/share`
   - 输入分享ID: `1`
   - 点击查询
   - 检查 Network: `GET /api/admin/inspector/share/1`

**如果出现 401/403**:
- Token 未正确携带
- 用户没有 ADMIN 权限
- Token 已过期

## 五、常见问题排查

### Q1: 访问 /admin/ 出现 404

**检查步骤**:
```bash
# 1. 确认静态文件存在
ls -la /var/www/guanzhi-admin-web/
# 应该看到 index.html

# 2. 检查 Nginx 配置
sudo nginx -t

# 3. 查看 Nginx 错误日志
sudo tail -50 /var/log/nginx/guanzhi-admin-error.log
```

### Q2: API 请求出现 502 Bad Gateway

**原因**: Nginx 无法连接到后端 8085

**检查步骤**:
```bash
# 1. 确认后端服务运行中
lsof -i :8085

# 2. 测试本地连接
curl http://127.0.0.1:8085/user/info

# 3. 检查 Nginx 错误日志
sudo tail -50 /var/log/nginx/guanzhi-admin-error.log
```

### Q3: 登录后 Inspector 返回 401

**原因**: Token 权限问题

**检查步骤**:
```bash
# 1. 确认登录账号有 ADMIN 权限
mysql -u root -p
USE ONETTOO;
SELECT id, phone, nickname, role FROM userlist WHERE phone = '15810349766';
# role 字段应该是 'ADMIN'

# 2. 检查后端日志
tail -50 /root/onettoo/logs/onettoo-prod.log | grep -i "unauthorized\|401"
```

### Q4: 前端更新后看不到变化

**原因**: 浏览器缓存

**解决方案**:
```bash
# 1. 强制刷新浏览器 (Ctrl+F5 / Cmd+Shift+R)

# 2. 清除 Nginx 缓存(如果配置了缓存)
sudo rm -rf /var/cache/nginx/*

# 3. 确认文件已更新
ls -lht /var/www/guanzhi-admin-web/ | head
# 查看文件修改时间
```

## 六、更新流程

### 日常更新前端

1. **本地构建**:
```bash
cd "/Users/zaptain/Library/Mobile Documents/com~apple~CloudDocs/DarkForce/Seee/guanzhi/admin-web"
npm run build
tar czf admin-web-dist-$(date +%Y%m%d-%H%M%S).tar.gz dist
```

2. **备份当前版本** (服务器):
```bash
cd /var/www
sudo cp -r guanzhi-admin-web guanzhi-admin-web.backup-$(date +%Y%m%d-%H%M%S)
```

3. **上传并部署**:
```bash
# 上传(本地)
scp admin-web-dist-*.tar.gz ec2-user@52.83.127.15:/tmp/

# 部署(服务器)
cd /var/www/guanzhi-admin-web
sudo rm -rf ./*
sudo tar xzf /tmp/admin-web-dist-*.tar.gz --strip-components=1
sudo systemctl reload nginx
```

### 回滚到上一版本

```bash
cd /var/www
sudo rm -rf guanzhi-admin-web
sudo mv guanzhi-admin-web.backup-20251207-143000 guanzhi-admin-web
sudo systemctl reload nginx
```

## 七、安全建议

### 7.1 启用 HTTPS (推荐)

使用 Let's Encrypt 免费证书:
```bash
# 安装 certbot
sudo apt install -y certbot python3-certbot-nginx

# 自动配置 HTTPS
sudo certbot --nginx -d your-domain.com
```

### 7.2 限制 /admin 访问

只允许特定 IP 访问后台:
```nginx
location /admin/ {
    # 只允许办公网 IP
    allow 1.2.3.4;
    deny all;

    alias /var/www/guanzhi-admin-web/;
    try_files $uri $uri/ /admin/index.html;
    index index.html;
}
```

### 7.3 定期备份

```bash
# 添加到 crontab
0 2 * * * tar czf /backup/guanzhi-admin-web-$(date +\%Y\%m\%d).tar.gz /var/www/guanzhi-admin-web/
```
