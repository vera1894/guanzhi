# Agent 对话与行为规则

## 1. 核心工作流：使用前必读 (MUST READ)

**任何 Agent（包括 Gemini、Claude、GPT 等）在本项目中开始任何实质性工作前，必须执行以下步骤以建立上下文：**

1.  **进入根目录**：确保当前工作目录为项目根目录。
2.  **读取核心规则**：阅读 `projectBasicInfo/00_AGENT_RULES.md`，了解 Agent 的统一行为准则、角色分工及操作原则。
3.  **建立项目认知**：阅读 `projectBasicInfo/01_PROJECT_OVERVIEW.md`，快速掌握项目结构、技术栈、生产环境架构及 AI 角色分工，**不要依赖历史对话记忆**。
4.  **获取连接与凭据** (如涉及)：
    *   阅读 `projectBasicInfo/02_CONNECTIONS.private.md` 获取服务器连接、仓库地址、部署入口等信息。
    *   阅读 `projectBasicInfo/03_CREDENTIALS.private.md` 获取账号、Token、密钥等敏感信息（注意：此文件严禁提交到 Git）。

## 2. 语言与沟通规范

*   **中文回复**：所有 Agent 对话回复必须使用中文。
*   **代码注释**：根据上下文使用中文或英文，保持风格一致。
*   **术语使用**：技术术语可使用英文，但必要时提供中文解释。
*   **文件命名**：严格保持原有的命名方式，不随意更改。

### 2.1 术语规范（重要）

**详细规范请参阅** `projectBasicInfo/04_TERMINOLOGY.md`

| 层面 | 使用术语 | 示例 |
|------|----------|------|
| **UI 文案**（用户可见） | 观之 | "发布观之"、"暂无观之" |
| **代码类型/变量名** | Share | `struct Share`、`shareId` |
| **API/数据库** | share | `/shares/`、`share` 表 |

**禁止改动**：Swift 类型名、变量名、API 路径、数据库结构

## 3. 日志与记录规范

*   **统一日志目录**：所有重大操作（如部署、架构变更、复杂 Bug 修复等）的记录，**必须** 归档到 `projectBasicInfo/logs/` 目录下。不要再散落在其他目录。
*   **日志命名格式**：`YYYY-MM-DD-英文主题-角色.md`（例如：`2025-12-08-admin-web-deploy-gemini.md`）。
*   **日志内容结构**：
    *   **背景**：为什么做这次操作。
    *   **环境**：本地/测试/生产。
    *   **实施步骤**：实际执行的命令、修改的配置。
    *   **验证结果**：接口测试结论、截图、日志片段。
    *   **TODO/风险**：遗留问题或注意事项。

## 4. 辅助文档说明 (参考用)

虽然 `projectBasicInfo/` 是最新的核心入口，但以下文档在特定场景下仍具参考价值：

*   **PROJECT_SUMMARY.md**: 包含更详细的代码级架构分析、设计模式和模块职责。
*   **CONTEXT_MANAGER.md**: 说明了上下文管理脚本的使用（辅助工具）。
*   **PROJECT_CONTEXT.md**: 记录了较早期的开发状态和待办事项（注意检查时效性）。
