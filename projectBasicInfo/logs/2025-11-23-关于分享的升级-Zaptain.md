# 关于分享的升级
#Seee

根据本项目Server中的后端代码和前端所有涉及的接口代码考虑下面的分享和用户系统升级优化，注意后端代码中只有“观之”部分是用于此项目的：
* 分享具有的属性：
  * 查看：「被查看次数」记录此分享被查看的次数，在UI上不展示
    * viewUserCount（去重查看人数）：只统计“有多少不同的 userId 看过这条分享”，使用这个数据作为统计标准
    * recentViewUserCount：最近 N 天（比如 7 天）去重浏览人数（可选，用于更精准的褪色），这个数据先只用于分析
* 赞同：「赞同」、「无感」，任意地理位置的人都可以点击一次赞同或无感，两者互斥
  * 以后UI上的补充：“当一条分享被很多人看过，但大家都只是‘无感’，系统会自动降低它在公共地图上的存在感。”
* 评论：用户到达此分享的地理位置200m以内才可进行评论，初期只做一级评论，但保留顺畅升级到二级评论的能力
* 打卡：用户到达此分享的地理位置200m以内才可进行打卡
  * 打卡和评论的定位可以共用一套「距离校验逻辑」，避免两套代码
* 贴标签：包括多种标签类型，由“有权限的用户”贴上，这是对于分享的描述，这些标签暂时由官方创建，比如「秘境」的标签如果足够多，就会被持续展示
  * 所有被发出的分享，初期均不带标签，视为“随意发的”
  * 有权限的用户：社区管家（官方账号）、超级用户（达到一定等级的普通用户）
  * 标签：
    * 「秘境」（野生好地点）
    * 「珍馐」
    * 「玩趣」
    * 「踩坑预警」
    * 「猫猫出没」
    * 「朝圣」
    * 「日出」
    * 「集市」
    * 。。。
* 违法：被他人举报，且被管理员标记为违法，这个帖子将被所有范围内不可见
  * 对公共地图隐藏 + 分享者在自己的「我的分享」里看到一条灰色记录，写明「因违反规定已下架，仅自己可见」
* 褪色度：因为图片直接显示在地图上，在热门地区一定会有很多质量偏低的分享，褪色度的目的是当分享的“评分”达到低于一定程度时，这个分享就会“褪色”，在公共区域不可见，只存在于发送者自己的分享列表历史中
  * “评分”（fadeScore）是综合以上多种维度和时间来计算的，比如：一个没有赞同、评论但被查看过多次的图片，会在一定时间内褪色；一个有不赞同的分享，会更快褪色；一个没被查看过的分享，则会持续存在。
  * fadeScore 的公式（初版）：褪色度达到 100 时视为褪色，初始值为 0
    * 当 viewUserCount = 0 → 每日基础褪色值 baseFadeDaily = 0 → 没人看过的分享，fadeScore 永远停在 0，不会自然褪色
    * 当 viewUserCount >= 1 时，分档计算：
      * | 1 – 5 人 | +2 |
      * | 6 – 20 人 | +4 |
      * | 21 – 50 人 | +6 |
      * | 51 – 100 人 | +8 |
      * | > 100 人 | +10（封顶） |
    * 赞同 -2 / 无感 +2
    * 打卡 -5 / 评论 -5
    * 被一个用户贴标签 1 次，每日增加值 -0.5，每个有权限用户对该分享至少贴过一个标签，则这个用户为该分享提供 -0.5 的每日减速，按用户去重，不按标签个数叠加。最终的每日自然褪色值保持在 [0, 10] 之间，避免负值或超过上限
    * 官方标记：
      * 无标记（默认）：无影响
      * 好标记：褪色度冻结为 0
      * 坏标记：褪色度冻结为 100
    * fadeScore 的更新做成定时任务（每日或每 N 小时批处理），而不是每次埋点实时算。赞同 / 无感 / 打卡 / 评论发生时立即调整 fadeScore（事件型增减），每日任务只负责按查看人数和标签做自然褪色推进。
    * UI 上可考虑：0 – 40 正常展示/ 40 – 80 地图上略微透明、缩放到较大区域时才出现 / ≥100 公共地图隐藏。40–80 区间只影响「地图显示样式」，不影响分享在列表或详情中的可见性，这个 UI 优先级较低
* 用户具有的属性：
  * 积分：用户通过行为获得积分，积分用来评判用户对社区的贡献程度，以获得身份或其他奖励。积分规则如下（初版）：
    * 发送分享：+2，每日上限 10
    * 查看分享：+1，每日上限 10（“查看分享”和“赞同/无感”的积分只计入**有效行为**，如需要打开详情且图片加载成功，同一分享不重复计分，具体规则由后端/风控细化）
    * 赞同/无感 分享：+1，每日上限 10（当天对**不同分享**的行为才能计入，防止一个用户对自己某个分享反复点来回切换想刷上限）
    * 打卡分享：+5，每日上限 25（每个分享只取一次打卡分）
    * 评论分享：+5，每日上限 25（每个分享只取一次评论分）
    * 违法：-100，无每日上限
    * 贴标签：+5，每日上限 25（单个用户对单个分享无论贴几个标签，仅加一次分）
    * 被贴标签：+5，每日上限 25（单个用户对单个分享无论贴几个标签，仅加一次分）
  * 等级：用于区分用户所能做出的行为，对用户出门探索进行鼓励
    * 游民：初始等级
    * 冲浪：一个比较容易获得的等级
      * 积分>100
    * 潜水：
      * 积分>4000
      * 打卡>20
      * 评论>10
    * 蓝洞：到达此等级之后拥有贴部分标签权限，每日限 10 枚标签
      * 对拥有贴标签权限的用户，可根据「其贴标签对应的内容后续被判违法 / 被大量无感」等指标，评估其标签质量，极端情况下可以收回贴标签权限。
      * 积分>10000
      * 打卡>200
      * 评论>100
    * 水母：达此等级之后拥有贴全部标签权限，每日限 20 枚标签
      * 积分>50000
      * 打卡>1000
      * 评论>500
      * 打卡某一标签的分享>100
    * 灯塔（传奇）：？？？等待定义
  * 奖章：用于激发用户进行各种探索以及参加未来的社区活动（奖章获得方法用户不可见）
    * 游民奖章：
      * 条件：奖章系统上线时，即发放
      * 说明：加入观之，成为社区游民，一个不错的开始。
    * 具备冲浪资质：
      * 条件：查看分享数>50
      * 说明：人在屋中坐，世界天上来。
    * 冲浪专家：
      * 条件：累计查看分享数>500
      * 说明：待定
    * 定点分析师：
      * 条件：一次连续查看 300个分享，每次需要点开，图片要加载成功
      * 说明：待定
    * 猫猫观察员：
      * 条件：打卡标签为「猫猫出没」的分享数>100
      * 说明：待定
    * 街溜子：
      * 条件：打卡分享数>300
      * 说明：待定
    * 。。。。
  * 用户状态：
    * 正常：默认状态
    * 警告：被社区警告，可能会损失各种数值，持续 15 天后自行解除。警告期间仍可进行各种功能操作，只是提示用户被警告了
    * 冻结：被社区处理，账号处于不可用状态，可以登录但「只读」

### 2. 分享互动相关 API 设计与实现

### 2.1 查看统计

**目标**：
* 每个 userId 对同一分享的「查看」最多计 1 次，用于计算 viewUserCount。
* 不在 UI 展示查看数。

⠀
**建议接口与逻辑：**
1. POST /api/guan/share/view
   * 入参：shareId
   * 鉴权：需要登录（否则无法统计去重用户）
   * 逻辑：
     * 通过 JWT/上下文获取 userId
     * 判断该用户是否已观看过此分享（查 Redis Set 或 share_view_user 表）
     * 若未看过：
       * 记录 (shareId, userId)
       * share_stats.view_user_count++
     * 无需返回计数，只返回成功/失败。

⠀
任务：
	* 在现有 ShareController / GuanShareController 中增加上述接口。
	* 写单元/集成测试，验证去重逻辑。

### 2.2 赞同 / 无感

**业务规则：**
* 任意地理位置可操作。
* 同一用户对同一分享只有三种状态：未投票 / 赞同 / 无感。
* 状态切换：
  * 未投票 → 赞同
  * 未投票 → 无感
  * 赞同 → 无感 / 取消赞同（自定是否允许回到“未投票”）
  * 无感 → 赞同 / 取消无感

⠀
**积分规则：**
* 赞同/无感 分享：+1，每日上限 10（当天对不同分享的行为才计入）

⠀
**褪色度规则：**
* 赞同：fadeScore -= 2
* 无感：fadeScore += 2

⠀
**接口建议：**
1. POST /api/guan/share/vote
   * 入参：shareId, voteType（1=赞同，0=无感，-1=取消）
   * 鉴权：需要登录
   * 逻辑：
     * 根据 (shareId, userId) 查询 share_vote 记录
     * 更新或插入 voteType
     * 更新 share_stats.agree_count / neutral_count
     * 触发相应的 fadeScore 调整
     * 根据积分规则写 user_points_log 并更新用户积分（控制每日上限）
   * 出参：
     * 当前该分享的统计数据（agree_count, neutral_count, userVoteType 等）

⠀
⸻

### 2.3 评论

**规则：**
* 200m 内才能评论。
* 初期只做一级评论（parentId 可为 0/null）。
* 每个分享对同一用户的评论数**积分只取第一次**。

⠀
**接口建议：**
1. POST /api/guan/share/comment/add
   * 入参：shareId, content, latitude, longitude
   * 鉴权：登录
   * 逻辑：
     * 校验距离：使用统一的「距离校验逻辑」，确认在 200m 内；
     * 写入 share_comment；
     * share_stats.comment_count++；
     * fadeScore：-5；
     * 写积分（+5，每日上限 25，同一分享只加一次）。
2. GET /api/guan/share/comment/list
   * 入参：shareId, page, pageSize
   * 返回：
     * 评论列表：user, content, createdAt
   * 后续扩展二级评论时，可基于 parent_id 扩展。

### 2.5 贴标签（有权限用户）

**业务规则：**
* 标签由官方维护（在配置表或枚举中定义）。
* 初始化时所有分享无标签（视为“随意发的”）。
* 有权限用户：社区管家（官方账号）、高等级用户（蓝洞/水母）。
* 同一有权限用户对同一分享，可以贴多个标签，但对“每日减速”只算 1 个用户。
* 标签类型示例：
  * MIJING（秘境）
  * ZHENXIU（珍馐）
  * WANQU（玩趣）
  * CAIKENG（踩坑预警）
  * MAOMAO（猫猫出没）
  * CHAOSHENG（朝圣）
  * RICHU（日出）
  * JISHI（集市）
  * …

⠀
**积分规则：**
* 贴标签：+5，每日上限 25（单个用户对单个分享多标签只加一次分）
* 被贴标签：+5，每日上限 25（单个用户对单个分享无论贴几个标签，仅加一次分）

⠀
**褪色度规则：**
* 每个有权限用户只要对该分享贴过至少一个标签，即为该分享提供 -0.5 的每日自然褪色减速。

⠀
**接口建议：**
1. POST /api/guan/share/tag
   * 入参：shareId, tagCode, action（1=添加, 0=取消）
   * 鉴权：登录 + 权限校验（根据用户等级）
   * 逻辑：
     * 更新 share_tag_user；

### 3. 褪色度 fadeScore 实现

### 3.1 事件型调整（即时）

在以下事件发生时立刻调整 fadeScore：
* 赞同：fadeScore -= 2
* 无感：fadeScore += 2
* 打卡：fadeScore -= 5
* 评论：fadeScore -= 5

⠀
要求：保证 fadeScore 不会低于 0，可在更新时 max(0, fadeScore + delta)。

### 3.2 自然褪色（定时任务）

**每日/每 N 小时批处理：**
1. 对所有 status != ILLEGAL 的分享执行：
   * 若 viewUserCount == 0：
     * baseFadeDaily = 0（不自然褪色）
   * 若 viewUserCount >= 1，按分档计算 baseFadeDaily：

⠀
**viewUserCount**	**baseFadeDaily**
1 – 5	+2
6 – 20	+4
21 – 50	+6
51 – 100	+8
> 100	+10


	* 计算标签带来的减速：

⠀labelBonusDaily = -0.5 * 有权限标签用户数（按 user 去重）
	* naturalFadeDaily = clamp(baseFadeDaily + labelBonusDaily, 0, 10)
	* 更新：fadeScore = min(fadeScore + naturalFadeDaily, 100)（不超过 100）

⠀
2. 根据 fadeScore 更新 status：
   * < 100：按 0–40 / 40–80 供前端做 UI 处理（不改 status）
   * > = 100：status = HIDDEN（公共地图隐藏，仅作者可见）
3. 官方标记：
   * 好标记：将 fadeScore 置 0，并在以后的自然褪色任务中跳过该分享；
   * 坏标记：将 fadeScore 置 100，并设为 HIDDEN / ILLEGAL（根据业务需要二选一）。

⠀
**实现方式：**
* 使用当前项目里已有的定时任务机制（如 Spring @Scheduled）。
* 控制单次批处理的分页与性能（避免一次处理全表）。
