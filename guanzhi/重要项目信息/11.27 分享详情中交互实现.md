  ---
  二、实施方案：乐观更新（Optimistic Update）

  核心思想

  1. 立即更新UI：用户点击时，不等待服务器响应，直接更新本地状态和计数
  2. 后台同步：异步发送请求到服务器
  3. 失败回滚：如果请求失败，恢复原始状态并提示用户
  4. 定期校准：通过刷新详情或列表，同步服务器真实数据

  为什么这样做？

  - ✅ 用户体验极佳：点击即刻响应，无等待感（Instagram、微信都这样做）
  - ✅ 容错性强：即使网络较慢，UI不会卡顿
  - ✅ 最终一致性：通过定期同步保证数据准确

  /// 对分享进行投票
  /// - Parameters:
  ///   - shareId: 分享ID
  ///   - voteType: 投票类型 (1=赞同, 0=无感, -1=取消)
  /// - Returns: 空结果（成功/失败）
  func voteShare(shareId: Int64, voteType: Int) async throws {
      let data = try await OTONetwork.request(
          .voteShare(shareId: shareId, voteType: voteType)
      )

      let decoder = JSONDecoder()
      let response = try decoder.decode(OTOResponseModel<EmptyData>.self,
  from: data)

      guard response.respCode == 0 else {
          throw NSError(
              domain: "ShareService",
              code: response.respCode,
              userInfo: [NSLocalizedDescriptionKey: response.respMsg ??
  "投票失败"]
          )
      }
  }

  步骤 3: 实现乐观更新逻辑

  创建一个专门的 ViewModel 来管理点赞状态：

  新建文件: guanzhi/View/SharePages/ShareInteractionViewModel.swift

  import Foundation
  import Combine

  @MainActor
  class ShareInteractionViewModel: ObservableObject {
      @Published var isLiked: Bool = false
      @Published var likeCount: Int = 0
      @Published var isAnimating: Bool = false

      private var originalLiked: Bool = false
      private var originalCount: Int = 0
      private var currentShareId: Int64?

      // 初始化（从服务器数据加载）
      func initialize(share: Share) {
          self.currentShareId = share.id
          self.likeCount = share.agreeCount

          // 判断当前用户是否已点赞（从 share.currentUserVoteType 获取）
          self.isLiked = share.currentUserVoteType == 1

          // 保存原始值，用于失败回滚
          self.originalLiked = self.isLiked
          self.originalCount = self.likeCount
      }

      // 处理点赞/取消点赞
      func toggleLike() {
          guard let shareId = currentShareId else { return }

          // 1. 乐观更新 UI（立即响应）
          let wasLiked = isLiked
          isLiked.toggle()
          likeCount += isLiked ? 1 : -1
          isAnimating = true

          // 2. 动画结束后重置
          Task {
              try? await Task.sleep(nanoseconds: 500_000_000) // 0.5秒
              isAnimating = false
          }

          // 3. 后台同步到服务器
          Task {
              do {
                  let voteType = isLiked ? 1 : -1  // 1=赞同, -1=取消
                  try await ShareService.shared.voteShare(
                      shareId: shareId,
                      voteType: voteType
                  )

                  // 成功后更新原始值（用于下次比较）
                  originalLiked = isLiked
                  originalCount = likeCount

                  print("✅ 点赞操作成功")
              } catch {
                  // 4. 失败时回滚 UI
                  print("❌ 点赞操作失败: \(error.localizedDescription)")
                  await rollback(wasLiked: wasLiked)

                  // TODO: 显示错误提示给用户
              }
          }
      }

      // 回滚到之前的状态
      private func rollback(wasLiked: Bool) async {
          await MainActor.run {
              isLiked = wasLiked
              likeCount = originalCount

              // TODO: 显示 Toast 提示 "操作失败，请重试"
          }
      }
  }

  四、关键技术点

  1. 为什么不等待服务器响应？

  | 方案   | 响应时间      | 用户体验    | 复杂度 |
  |------|-----------|---------|-----|
  | 同步等待 | 100-500ms | ❌ 卡顿感明显 | 简单  |
  | 乐观更新 | <16ms     | ✅ 即时响应  | 中等  |

  2. 如何保证数据一致性？

  - 定期同步: 用户刷新详情页时，从服务器拉取最新数据
  - 失败回滚: 请求失败时立即恢复原状态
  - 冲突处理: 服务器数据为准（最终一致性）

  五、测试建议

  1. 正常流程: 点赞 → 取消 → 再点赞
  2. 网络失败: 关闭网络 → 点赞 → 观察回滚
  3. 快速点击: 连续快速点击10次，检查计数是否正确
  4. 并发冲突: 两个设备同时点赞同一条分享
  5. 数据同步: 点赞后退出详情页，再进入，检查计数是否持久化

  ---
  六、后续优化方向

  1. 本地缓存: 使用 SwiftData 持久化点赞状态
  2. 离线队列: 网络断开时，将操作放入队列，恢复后自动同步
  3. 防抖动: 连续点击时，合并请求（debounce）
  4. 动画升级: 添加粒子效果、震动反馈（Haptic Feedback）

  ✅ 总结

  这个方案的优势：
  1. 业界标准：微信、Instagram、抖音都用这个模式
  2. 用户体验好：点击即响应，无等待
  3. 可靠性强：失败会回滚，定期同步保证一致性
  4. 易于扩展：同样逻辑可用于打卡、评论等功能
