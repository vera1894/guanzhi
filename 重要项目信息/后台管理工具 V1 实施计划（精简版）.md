## 🎯 V1 核心定位

基于 GPT 专家建议，V1 专注于：

> **"对后端的数据表和算法进行查看和控制"**

### V1 做什么（配置 + 观察）
- ✅ 查看和编辑核心配置表

### ⭐ 模块 5：算法模拟器（核心创新）

**功能**：实时模拟参数调整对算法的影响

#### 🔧 计算逻辑维护方案（关键设计决策）

**问题**：褪色公式如果前后端不同步，会导致"面板显示 A，实际运行是 B"

**解决方案（二选一）**：

##### 方案 A：后端计算（推荐 ⭐）
**优势**：
- ✅ 单一真相来源（后端改公式，前端自动同步）
- ✅ 复杂公式无需翻译成 JavaScript
- ✅ 未来公式升级，前端无需修改

**实现**：
1. 新增后端接口：
```java
// AdminController.java
@PostMapping("/admin/fade/simulate")
public ResponseEntity<FadeSimulationResult> simulateFadeScore(
    @RequestBody FadeSimulationRequest request
) {
    // request: { viewCount, agreeCount, neutralCount, tagIds, daysSincePost, districtCode }
    // 1. 根据 districtCode 获取对应 fade_config
    // 2. 调用现有的 fadeScore 计算逻辑
    // 3. 生成 1/3/7/15/30/60/90 天的曲线数据
    // 4. 返回 { currentScore, timeline: [day1, day7, ...], scores: [92, 85, ...] }
}
```

2. 前端调用：
```javascript
const response = await axios.post('/api/admin/fade/simulate', {
  viewCount: 500,
  agreeCount: 50,
  neutralCount: 10,
  tagIds: [1, 2],
  daysSincePost: 7,
  districtCode: '310115'
})

// 绘制折线图
drawChart(response.data.timeline, response.data.scores)
```

##### 方案 B：前端计算（备选）
**优势**：
- ✅ 响应速度快（无网络请求）
- ✅ 可离线使用

**劣势**：
- ❌ 公式需要手动同步
- ❌ JavaScript 翻译可能有精度问题

**实现**：
1. 后端提供公式版本接口：
```java
@GetMapping("/admin/fade/formula-version")
public String getFormulaVersion() {
    return "v1.2.0";  // 每次改公式时递增
}
```

2. 前端启动时检查：
```javascript
const serverVersion = await getFormulaVersion()
const localVersion = 'v1.2.0'  // 硬编码在前端

if (serverVersion !== localVersion) {
  alert('⚠️ 褪色公式已更新，请联系管理员更新前端代码')
}
```

**✅ V1 采用方案 A（后端计算）**
- 理由：更安全、更易维护，适合"工程师工具"定位

## 🏗️ 技术架构

### 前端技术栈
- **框架**：Vue 3 + Vite
- **UI 库**：Element Plus（简洁、企业级、不花哨）
- **图表库**：ECharts（用于折线图）
- **HTTP 客户端**：Axios（封装 JWT 认证）

### 后端依赖
- **无需修改后端代码**：完全使用现有的 `AdminController` 接口
- **新增接口（可选）**：
  - `POST /api/admin/simulate/fadeScore`（褪色模拟，可在前端本地实现公式）
  - `POST /api/admin/simulate/level`（等级模拟，同上）

### 部署架构
```
浏览器
  ↓ HTTPS
Nginx (onettoo.com)
  ├─ /admin/* → 静态文件（Vue 构建产物）
  └─ /api/*   → 反向代理到 localhost:8085
                  ↓
          Spring Boot AdminController
                  ↓
               MySQL 数据库
```

**访问方式**：
- URL：`https://onettoo.com/admin` 或 `https://admin.onettoo.com`
- 登录：输入账号密码，后端验证 `ROLE_ADMIN` 权限

### 3. 配置变更日志系统（关键保护机制）

**目的**：
- 📝 记录谁、什么时候、改了什么配置
- 🔍 排查问题（如"褪色规则突然变了，谁改的？"）
- 🔙 支持手动回滚（查看历史值，恢复旧配置）

#### 3.1 数据库表设计

```sql
-- 新建配置变更日志表
CREATE TABLE `admin_operation_log` (
  `id` BIGINT(20) NOT NULL AUTO_INCREMENT,
  `user_id` BIGINT(20) NOT NULL COMMENT '操作人用户ID',
  `username` VARCHAR(64) NOT NULL COMMENT '操作人用户名',
  `module` VARCHAR(32) NOT NULL COMMENT '模块名（points_rules/levels/tags/fade_config）',
  `action` VARCHAR(16) NOT NULL COMMENT '操作类型（create/update/delete）',
  `record_id` BIGINT(20) DEFAULT NULL COMMENT '被操作记录的ID',
  `before_value` JSON DEFAULT NULL COMMENT '修改前的值（JSON格式）',
  `after_value` JSON DEFAULT NULL COMMENT '修改后的值（JSON格式）',
  `ip_address` VARCHAR(64) DEFAULT NULL COMMENT '操作人IP',
  `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  INDEX `idx_user_id` (`user_id`),
  INDEX `idx_module_action` (`module`, `action`),
  INDEX `idx_created_at` (`created_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='管理后台操作日志';
```

#### 3.2 后端接口设计

**新增日志记录方法**（在每个 save/update/delete 接口中调用）：

```java
// AdminController.java

@Autowired
private AdminOperationLogService logService;

@PostMapping("/admin/fade/save")
public ResponseEntity<?> saveFadeConfig(@RequestBody FadeConfig newConfig) {
    // 1. 获取修改前的值（如果是更新）
    FadeConfig oldConfig = fadeConfigRepository.findById(newConfig.getId()).orElse(null);

    // 2. 执行保存操作
    fadeConfigRepository.save(newConfig);

    // 3. 记录变更日志
    logService.recordChange(
        getCurrentUserId(),
        getCurrentUsername(),
        "fade_config",
        oldConfig == null ? "create" : "update",
        newConfig.getId(),
        oldConfig,  // before_value
        newConfig,  // after_value
        getClientIP()
    );

    return ResponseEntity.ok("保存成功");
}
```

#### 3.3 前端集成（自动记录）

前端在 Axios 响应拦截器中自动处理：

```javascript
// axios.interceptors.response.js

axios.interceptors.response.use(
  response => {
    // 所有 save/update/delete 操作成功后，自动记录
    if (response.config.method !== 'get') {
```

## 📦 Nginx 部署配置

```nginx
# /etc/nginx/sites-available/onettoo.com.conf

server {
    listen 443 ssl;
    server_name onettoo.com;

    ssl_certificate /path/to/cert.pem;
    ssl_certificate_key /path/to/key.pem;

    # 1. 管理后台静态文件
    location /admin {
        alias /var/www/admin-panel/dist;
        try_files $uri $uri/ /admin/index.html;
        index index.html;
    }

    # 2. 后端 API 反向代理
    location /api/ {
        proxy_pass http://localhost:8085;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }

    # 3. 其他路径（移动端 API 等）
    # ...
}
```

**部署步骤**：

## 💡 关键决策（包含 GPT 专家建议）

### 决策 1：V1 不做用户管理
**理由**：
- 用户管理是"运营后台"的需求，当前重点是"算法调试"
- 减少 scope，快速上线核心功能（10-12 天 vs 15-23 天）

### 决策 2：算法模拟器是 V1 核心
**理由**：
- **这是 V1 的核心价值**：让"算法"变成可对话、可观察的工具
- 避免"盲调参数"，通过可视化理解算法行为
- 这是原始诉求中"查看算法"的真正体现

### 决策 3：结构化表单 > 自由 JSON
**理由**（GPT 建议）：
- 降低出错率（JSON 格式错误会"一行打死系统"）
- 提升可用性（普通运营也能操作）
- 保持"简洁好用"的设计原则

### ⭐ 决策 4：后端计算 > 前端计算（褪色模拟器）
**理由**（GPT 关键建议）：
- ✅ **单一真相来源**：后端改公式，前端自动同步
- ✅ **避免同步问题**：不会出现"面板显示 A，实际运行 B"
- ✅ **易于维护**：复杂公式无需翻译成 JavaScript
- ❌ 备选方案（前端计算）风险高：公式版本不一致、精度问题

**实现**：
- 后端新增 `/api/admin/fade/simulate` 接口
- 前端只负责输入参数、调用接口、绘制图表

### ⭐ 决策 5：必须有配置变更日志系统
**理由**（GPT 关键建议）：
- ✅ **排查问题**：快速定位"谁在什么时候改了什么配置"
- ✅ **支持回滚**：记录 before/after 值，可手动恢复
- ✅ **审计追踪**：符合生产环境的安全规范

**实现**：
- 数据库新增 `admin_operation_log` 表
- 后端在所有 save/update/delete 接口中自动记录
- V1 只记录，V2 再做 UI 查看功能
