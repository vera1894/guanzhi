## 测试1：等级配置 (LevelsConfig)

### 测试目标
验证新字段显示和保存功能（移除了maxPoints和description，添加了minCheckins, minComments, taggingAllowance, extraConditions）

### 操作步骤

#### 1.1 查看列表
**操作**: 点击左侧菜单 "等级配置"

**预期结果**:
- ✅ 页面正常加载
- ✅ 显示5条数据（游民、冲浪、潜水、蓝洞、水母）
- ✅ 表格显示以下列：ID、等级代码、等级名称、最小积分、最小打卡、最小评论、标签配额、额外条件、操作
- ✅ **不显示** maxPoints 和 description 列

**验证点**:
```
| ID | 等级代码 | 等级名称 | 最小积分 | 最小打卡 | 最小评论 | 标签配额 | 额外条件 |
|----|---------|---------|---------|---------|---------|---------|---------|
| 1  | YOMIN   | 游民     | 0       | 0       | 0       | 0       | (空)    |
| 2  | CHONGLANG| 冲浪    | 200     | 0       | 0       | 0       | (空)    |
| 5  | SHUIMU  | 水母     | 50000   | 1000    | 500     | 20      | (空)    |
```

#### 1.2 新增等级
**操作**: 点击 "新增等级" 按钮

**预期结果**:
- ✅ 弹窗打开
- ✅ 显示以下输入框：
  - 等级代码 (文本)
  - 等级名称 (文本)
  - 最小积分 (数字)
  - 最小打卡数 (数字)
  - 最小评论数 (数字)
  - 标签配额 (数字)
  - 额外条件 (多行文本)
- ✅ **不显示** maxPoints 和 description 输入框

**测试数据**:
```
等级代码: TEST_LV
等级名称: 测试等级
最小积分: 1000
最小打卡数: 5
最小评论数: 3
标签配额: 2
额外条件: {"testField": true}
```

**操作**: 填写数据后点击 "保存"

**预期结果**:
- ✅ 提示 "保存成功"
- ✅ 弹窗关闭
- ✅ 列表自动刷新，显示新增的记录

#### 1.3 编辑等级
**操作**: 点击刚才新增记录的 "编辑" 按钮

**预期结果**:
- ✅ 弹窗打开，所有字段正确回显
- ✅ 修改 "标签配额" 为 5
- ✅ 点击保存后成功

#### 1.4 验证数据持久化
**操作**: 点击页面的 "刷新" 按钮

**预期结果**:
- ✅ 列表重新加载
- ✅ 刚才修改的数据仍然存在且正确

**打开开发者工具验证**:
1. 按 F12 打开控制台
2. 切换到 "Network" 标签
3. 点击 "刷新" 按钮
4. 查看 `/api/admin/config/levels` 请求
   - ✅ 状态码: 200
   - ✅ 响应包含新增的记录
   - ✅ 响应字段包含: minCheckins, minComments, taggingAllowance, extraConditions

#### 1.5 删除测试数据
**操作**: 点击测试记录的 "删除" 按钮，确认删除

**预期结果**:
- ✅ 提示 "删除成功"
- ✅ 列表更新，测试记录消失

## 测试4：褪色配置 (FadeConfig)

### 测试目标
修复400错误，验证保存功能

### 操作步骤

#### 4.1 查看列表
**操作**: 点击 "褪色配置"

**预期结果**:
- ✅ 显示配置列表（VIEW_COUNT_FADE_TIER_1 等）
- ✅ 表格显示：ID、配置键、配置值、说明、操作

#### 4.2 编辑配置 - 测试保存
**操作**: 编辑第一条记录

**原始数据**:
```
配置键: VIEW_COUNT_FADE_TIER_1
配置值: 5:3
说明: 阅读量第一档：<=5人阅读时，每天增加3分褪色分
```

**修改**:
```
配置值: 5:3.5  (修改小数点)
```

**操作**: 点击保存

**预期结果**:
- ✅ 保存成功（如果之前有400错误，现在应该修复）
- ✅ 刷新后配置值正确显示为 "5:3.5"

**如果出现400错误，打开开发者工具检查**:
1. 查看 POST `/api/admin/config/fade-config` 请求
2. 请求体格式应该是：
```json
{
  "id": 1,
  "configKey": "VIEW_COUNT_FADE_TIER_1",
  "configValue": "5:3.5",
  "description": "阅读量第一档..."
}
```
3. 如果字段不对，需要修复前端代码

#### 4.3 恢复原始数据
**操作**: 将配置值改回 "5:3"
