## 一、管理员角色定义分析

### 1.1 代码位置

**Inspector接口权限要求**：
- 文件：`AdminInspectorController.java:20`
- 注解：`@PreAuthorize("hasAnyRole('ROLE_ADMIN')")`

**角色生成逻辑**：
- 文件：`UserDetailsServiceImpl.java:46-47`
```java
if (StrUtil.isNotBlank(user.getRole())) {
    authorities = AuthorityUtils.commaSeparatedStringToAuthorityList("ROLE_" + user.getRole());
}
```

### 1.2 关键发现

**角色处理机制**：
1. 数据库中存储的是 `role` 字段（例如：`"ADMIN"`）
2. 系统会自动添加 `"ROLE_"` 前缀
3. 最终生成的权限为 `"ROLE_ADMIN"`
4. Inspector接口要求 `ROLE_ADMIN` 权限

**结论**：需要将用户的 `role` 字段设置为 `'ADMIN'`（不带前缀）

## 二、数据库表结构分析

### 2.1 用户表

**表名**：`userlist`
**文件**：`UserDO.java:18`

**关键字段**：
```sql
id              BIGINT          -- 用户ID
phone           VARCHAR         -- 手机号
name            VARCHAR         -- 账号
nickname        VARCHAR         -- 昵称
role            VARCHAR         -- 用户角色（关键字段）
```

### 2.2 角色存储方式

本项目采用**简化的角色管理**：
- **不使用**独立的角色表（`sys_role`）
- **不使用**用户-角色映射表（`user_role`）
- **直接在用户表中**存储角色字符串（`role` 字段）

**优点**：
- 实现简单
- 查询高效（无需JOIN）
- 适合小型应用

## 八、故障排查

### 问题1：Token中没有 `"auth": "ROLE_ADMIN"`

**原因**：
- 数据库升级后，旧Token仍在Redis缓存中
- 或者数据库升级未生效

**解决方案**：
```bash
# 1. 清除Redis缓存（可选）
redis-cli -h 52.83.127.15 -p 6379 -a 'onettoo-redis-2023-onettoo.' FLUSHDB

# 2. 重新登录获取新Token
```

### 问题2：验证码未收到

**原因**：
- 手机号在管理员白名单中（会跳过发送）
- 短信服务未配置

**解决方案**：
```bash
# 查看日志确认
tail -f /root/onettoo/logs/onettoo-prod.log | grep "sendCode"
```

### 问题3：数据库连接失败

**原因**：
- 密码错误
- 数据库未启动

**解决方案**：
```bash
# 检查MySQL状态
systemctl status mysql

# 测试连接
mysql -h 127.0.0.1 -u root -p
```
