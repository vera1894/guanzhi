```bash

JAR=onettoo-0.0.1-SNAPSHOT.jar
nohup "$JAVA17" -jar "$JAR" --spring.profiles.active=prod >/dev/null 2>&1 &
```

**说明**:
- 使用 Amazon Corretto 17 作为 Java 运行时
- 激活 `prod` profile（生产环境配置）
- 后台运行（nohup），输出重定向到 `/dev/null`
- 日志通过 log4j2 配置写入 `target/` 目录

## 5. Nginx 反向代理配置

### 5.1 Nginx 基本信息

```
版本: nginx/1.24.x (需通过 nginx -v 确认)
配置文件: /etc/nginx/nginx.conf
运行用户: root
PID文件: /run/nginx.pid
错误日志: /var/log/nginx/error.log
访问日志: /var/log/nginx/access.log
```

### 5.2 核心配置摘要

**配置文件**: `/etc/nginx/nginx.conf`

```nginx
user root;
worker_processes auto;

http {
    # Upstream 配置
    upstream onettoo {
        server 127.0.0.1:8085;
    }

    upstream wanto {
        server 127.0.0.01:8000;
    }

    # HTTP服务器配置
    server {
        listen 80;
        server_name onettoo.com;
        client_max_body_size 1024m;  # 允许上传最大1GB文件

        # API反向代理
        location /api/ {
            proxy_set_header HOST $host;
            proxy_set_header X-Forwarded-Proto $scheme;
            proxy_set_header X-Real-IP $remote_addr;
            proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;

            proxy_pass http://onettoo/;
        }

        # 其他location配置...
    }

    # HTTPS配置 (443端口)
    # SSL证书位置:
    # - /etc/nginx/onettoo.com_bundle.pem (证书链)
    # - /etc/nginx/onettoo.com.key (私钥)
    # 备份文件:
    # - onettoo.com_bundle.pem.bak (2024-12-12)
    # - onettoo.com.key.bak
}
```

## 9. 故障排查指南

### 9.1 应用无法启动

#### 症状
- 执行 `start.sh` 后进程立即退出
- `lsof -ti:8085` 无输出

#### 排查步骤

**1. 查看错误日志**:
```bash
sudo tail -n 100 /root/onettoo/back/target/onettoo-error.log
```

**2. 检查端口冲突**:
```bash
sudo lsof -i:8085
# 如果有其他进程占用，先停止该进程
```

**3. 检查JAR包完整性**:
```bash
cd /root/onettoo/back/
sudo unzip -t onettoo-0.0.1-SNAPSHOT.jar | tail -5
# 如果显示错误，说明JAR包损坏，需要重新上传
```

**4. 检查Java版本**:
```bash
/usr/lib/jvm/java-17-amazon-corretto/bin/java -version
```

**5. 尝试前台运行查看详细错误**:
```bash
cd /root/onettoo/back/
sudo /usr/lib/jvm/java-17-amazon-corretto/bin/java \
    -jar onettoo-0.0.1-SNAPSHOT.jar \
    --spring.profiles.active=prod
# Ctrl+C 退出
```

### 9.2 数据库连接失败

**5. 检查MySQL配置**:

### 9.4 内存不足 (OOM)

#### 症状
- 进程突然退出
- 日志显示: `java.lang.OutOfMemoryError`
- 系统日志显示: `Out of memory: Kill process`

#### 排查步骤

**1. 查看系统内存**:
```bash
free -h
dmesg | grep -i "out of memory"
```

**2. 查看Java堆内存配置**:
```bash
ps aux | grep onettoo
# 检查是否有 -Xmx -Xms 参数
```

**3. 临时解决方案** - 修改启动脚本添加内存限制:
```bash
# 编辑 start.sh（仅示例，不执行）
nohup "$JAVA17" -Xms256m -Xmx512m -jar "$JAR" \
    --spring.profiles.active=prod >/dev/null 2>&1 &
```

**4. 长期解决方案**:
- 升级服务器配置（增加内存）
- 优化应用代码（减少内存占用）
- 启用Swap分区

### 9.5 磁盘空间不足

#### 症状

## 附录 D: 常见问题 FAQ

**Q1: 如何查看当前部署的应用版本？**

A: 应用版本信息在JAR包的MANIFEST.MF中，可以通过以下命令查看：
```bash
sudo unzip -p /root/onettoo/back/onettoo-0.0.1-SNAPSHOT.jar \
    META-INF/MANIFEST.MF | grep -E 'Implementation-Version|Build-Time'
```

**Q2: 为什么内存使用率这么高（81%）？**

A: 服务器总内存只有 905 MiB (约1GB)，运行 Java应用 + MySQL + Redis 确实紧张。建议：
- 升级到至少 2GB 内存的实例
- 或者优化Java堆内存设置（在start.sh中添加 `-Xmx512m`）

**Q3: 如何回滚到上一个版本？**

A:
```bash
cd /root/onettoo/back/
sudo kill -15 $(lsof -ti:8085)
sleep 3
sudo mv onettoo-0.0.1-SNAPSHOT.jar onettoo-0.0.1-SNAPSHOT.jar.failed
sudo cp onettoo-0.0.1-SNAPSHOT.jar.bak onettoo-0.0.1-SNAPSHOT.jar
sudo ./start.sh
```

**Q4: 如何清空Redis缓存？**

A:
```bash
redis-cli -h localhost -p 6379 -a 'onettoo-redis-2023-onettoo.' FLUSHALL
```
⚠️ 警告：这会删除所有缓存数据，慎用！

**Q5: 数据库备份文件太大怎么办？**

A: 使用压缩备份：
```bash
sudo mysqldump -u root -p'oneAa123123!.' ONETTOO | gzip > backup.sql.gz
```
压缩比通常可达 80-90%。
