## ⚠️ 当前问题（需修复）

### 问题1：前后端字段不一致

#### TagDefinitionDO（标签定义）
**后端实际字段**:
```java
{
  Long id;
  String tagCode;       // ← 前端用的是 tagKey
  String tagName;
  String minLevelCode;
  Boolean isActive;
  Integer sortOrder;
}
```

**前端期望字段**:
```typescript
{
  id?: number
  tagKey: string        // ❌ 应该是 tagCode
  tagName: string
  tagType: string       // ❌ 后端没有这个字段
  description?: string  // ❌ 后端没有这个字段
}
```

**修复方案**:
1. 修改前端 `src/api/admin.ts` 中的 `TagDefinition` 接口定义
2. 移除 `tagType` 和 `description` 字段
3. 将 `tagKey` 改为 `tagCode`
4. 在前端UI中移除对这些字段的引用

#### PointsRuleDO（积分规则）
**后端没有 `description` 字段**，前端需要移除。

#### LevelDefinitionDO（等级定义）
**后端没有 `maxPoints` 和 `description` 字段**，但有：
- `minCheckins`
- `minComments`
- `taggingAllowance`
- `extraConditions`

**修复方案**: 前端需要添加这些缺失的字段。

### 问题2：保存时可能出现400错误
由于字段不一致，保存操作可能失败。需要：
1. 确保发送给后端的请求体只包含后端认识的字段
2. 前端额外的字段只用于UI显示，不发送给后端

## 🔧 技术细节备忘

### Axios请求拦截器关键逻辑
```typescript
// 自动处理 Bearer 前缀
if (token && config.headers) {
  config.headers.Authorization = token.startsWith('Bearer ')
    ? token
    : `Bearer ${token}`
}
```

### 路由守卫关键逻辑
```typescript
router.beforeEach((to, from, next) => {
  const requiresAuth = to.meta.requiresAuth !== false
  const authenticated = isAuthenticated()

  if (requiresAuth && !authenticated) {
    next('/login')
  } else if (to.path === '/login' && authenticated) {
    next('/')
  } else {
    next()
  }
})
```

### 后端API响应格式
```json
{
  "respCode": 0,        // 0=成功
  "respMsg": "请求成功",
  "datas": { ... }      // 实际数据在这里
}
```
