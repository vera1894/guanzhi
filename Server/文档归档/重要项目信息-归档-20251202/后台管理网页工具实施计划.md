# 观之后台管理网页工具实施计划

## 📋 项目概述

### 背景
在后端升级 v1 中，我们将所有核心业务规则（积分、等级、奖章、标签、褪色参数等）从代码中解耦，存入数据库配置表中，并提供了完整的 RESTful Admin API（`AdminController`）。为了让非技术人员也能方便地管理这些配置，需要开发一个**网页管理工具**。

### 目标
构建一个简单、安全、易用的 Web 管理界面，让管理员可以通过浏览器实时调整系统参数，而无需重新部署后端服务。

### 核心价值
- ✅ **零部署调整**：修改业务规则不需要改代码、不需要重启服务
- ✅ **实时生效**：配置修改立即生效（通过缓存刷新机制）
- ✅ **降低门槛**：非技术人员也能管理系统参数
- ✅ **安全可控**：基于 JWT Token 的权限验证，只有管理员可访问

## 🎯 功能需求

### 1. 核心配置管理模块

#### 1.1 积分规则管理 (`/api/admin/config/points-rules`)
**功能**：
- 查看所有积分规则（表格展示）
- 新增积分规则
- 编辑积分规则（修改 `pointsValue`、`dailyLimit` 等）
- 删除积分规则

**数据字段**：
```json
{
  "id": 1,
  "actionType": "VOTE",         // 行为类型
  "pointsValue": 1,              // 获得积分
  "dailyLimit": 10,              // 每日上限
  "description": "投票（赞同/无感）"
}
```

**业务场景示例**：
- 运营希望提高用户活跃度，将 `VOTE` 的 `pointsValue` 从 1 改为 2
- 防止刷分，将 `CHECKIN` 的 `dailyLimit` 从无限改为 20

---

#### 1.2 等级定义管理 (`/api/admin/config/levels`)
**功能**：
- 查看所有用户等级（表格展示）
- 新增等级
- 编辑等级（修改积分门槛、复合条件等）
- 删除等级

**数据字段**：
```json
{
  "id": 1,
  "levelCode": "CHONGLANG",      // 等级代码
  "levelName": "冲浪",            // 等级名称
  "minPoints": 100,               // 最低积分要求
  "extraConditions": "{\"checkinCount\": 10}"  // JSON 格式的额外条件
}
```

**业务场景示例**：
- 调整 `SHUIMU` 等级门槛从 500 分提高到 800 分
- 为 `LANDONG` 等级增加额外条件：需要至少打卡 50 次

---

#### 1.3 奖章定义管理 (`/api/admin/config/medals`)
**功能**：
- 查看所有奖章（卡片展示）
- 新增奖章
- 编辑奖章（修改名称、描述、获得条件）
- 删除奖章

**数据字段**：
```json
{
  "id": 1,
  "medalCode": "STREETS_WALKER",
  "medalName": "街行者",
  "description": "累计打卡 300 次",
  "conditions": "{\"checkinCount\": 300}"
}
```

**业务场景示例**：
- 新增一个"资深观者"奖章，要求查看 1000 个分享
- 修改"海洋守护者"的描述文案

---

#### 1.4 标签定义管理 (`/api/admin/config/tags`)
**功能**：
- 查看所有标签及其权限要求（表格展示）
- 新增标签
- 编辑标签（修改权限等级、每日限额等）
- 删除标签

**数据字段**：
```json
{
  "id": 1,
  "tagCode": "MAOMAO",
  "tagName": "猫猫",
  "minLevelCode": "LANDONG",     // 最低等级要求
  "dailyLimit": 10,               // 每日可贴次数
  "fadeScoreBenefit": 3           // 对褪色度的影响
}
```

**业务场景示例**：
- 将"猫猫"标签的权限从 `LANDONG` 降低到 `CHONGLANG`
- 新增一个"美食"标签，只有 `SHUIMU` 等级才能贴

---

#### 1.5 褪色规则配置 (`/api/admin/config/fade-configs`)
**功能**：
- 查看所有褪色参数（键值对展示）
- 编辑参数值（修改各种加分/减分系数）

**数据字段**：
```json
{
  "AGREE_BONUS": "-2",        // 赞同时的褪色度变化
  "NEUTRAL_BONUS": "3",       // 无感时的褪色度变化
  "CHECKIN_BONUS": "-1",      // 打卡时的褪色度变化
  "VIEW_TIER_1_THRESHOLD": "50",
  "VIEW_TIER_1_INCREMENT": "2",
  ...
}
```

**业务场景示例**：
- 调整赞同的褪色减速效果，从 -2 改为 -5（让好分享更持久）
- 修改查看数分档阈值，从 50 改为 100

## 🛠 技术方案

### 技术栈选型

#### 方案 A：纯前端静态页面（推荐，快速实施）
```
前端技术栈:
- HTML5 + CSS3 + Vanilla JavaScript
- 或者 Vue 3 + Vite（如果需要更复杂的交互）
- Tailwind CSS 或 Bootstrap（快速搭建 UI）

特点:
✅ 开发快速（1-2周完成核心功能）
✅ 部署简单（直接放在 Nginx 静态目录）
✅ 维护成本低
❌ 缺少服务端渲染（但不影响管理后台使用）
```

#### 方案 B：Spring Boot + Thymeleaf（传统方案）
```
技术栈:
- Spring Boot MVC
- Thymeleaf 模板引擎
- Bootstrap

特点:
✅ 与后端集成紧密
✅ 服务端渲染，SEO 友好（虽然管理后台不需要）
❌ 开发周期较长（3-4周）
❌ 需要重新部署后端
```

#### 方案 C：React + Ant Design Admin（企业级）
```
技术栈:
- React 18
- Ant Design Pro
- TypeScript

特点:
✅ UI 组件丰富
✅ 开箱即用的后台模板
✅ 适合长期维护
❌ 开发周期最长（4-6周）
❌ 技术栈较重
```

### 推荐方案：**方案 A - Vue 3 + Vite + Element Plus**

**理由**：
1. **快速开发**：Vue 3 Composition API 简洁高效，Element Plus 提供完整的后台 UI 组件
2. **轻量部署**：编译后只是静态文件，放在 Nginx 即可
3. **易于维护**：代码结构清晰，后续迭代方便
4. **学习成本低**：Vue 生态成熟，文档完善

**技术细节**：
```
- Vue 3.3+
- Vite 5.0+
- Element Plus 2.4+（Table, Form, Dialog 等组件）
- Axios（HTTP 请求）
- Vue Router（路由管理）
- Pinia（状态管理，存储 Token 等）
```

### 认证流程

```
1. 管理员访问 https://onettoo.com/admin
   ↓
2. 判断本地是否有 Token
   - 有 → 验证 Token 是否过期
     - 未过期 → 进入管理后台
     - 已过期 → 跳转登录页
   - 无 → 跳转登录页
   ↓
3. 登录页输入手机号和验证码
   ↓
4. 调用 /api/guan/login 获取 Token
   ↓
5. 前端验证 Token 中是否包含 ROLE_ADMIN
   - 是 → 存储 Token，进入管理后台
   - 否 → 显示错误："您没有管理员权限"
   ↓
6. 所有 Admin API 请求携带 Authorization: Bearer {token}
```

## 📦 部署方案

### 部署架构

```
生产服务器:
┌────────────────────────────────┐
│  Nginx (:80/:443)              │
│                                │
│  /admin/*                      │
│  → /var/www/admin-web/dist/    │  (静态文件)
│                                │
│  /api/admin/*                  │
│  → http://localhost:8085/      │  (反向代理)
│                                │
└────────────────────────────────┘
```

### Nginx 配置示例

```nginx
# /etc/nginx/sites-available/onettoo-admin

server {
    listen 80;
    server_name admin.onettoo.com;  # 或者 onettoo.com/admin

    # 静态文件托管
    location /admin {
        alias /var/www/admin-web/dist;
        try_files $uri $uri/ /admin/index.html;
    }

    # API 反向代理
    location /api/admin {
        proxy_pass http://localhost:8085;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # HTTPS 配置（生产环境必须）
    # listen 443 ssl;
    # ssl_certificate /path/to/cert.pem;
    # ssl_certificate_key /path/to/key.pem;
}
```

### 部署步骤

1. **编译前端项目**
   ```bash
   cd admin-web
   npm install
   npm run build
   ```

2. **上传到服务器**
   ```bash
   scp -r dist/ user@server:/var/www/admin-web/
   ```

3. **配置 Nginx**
   ```bash
   sudo nano /etc/nginx/sites-available/onettoo-admin
   sudo ln -s /etc/nginx/sites-available/onettoo-admin /etc/nginx/sites-enabled/
   sudo nginx -t
   sudo systemctl reload nginx
   ```

4. **访问管理后台**
   ```
   https://onettoo.com/admin
   ```

## 🔒 安全考虑

### 1. 认证与授权
- ✅ **JWT Token 验证**：所有 Admin API 都有 `@PreAuthorize("hasAnyRole('ROLE_ADMIN')")`
- ✅ **前端权限检查**：登录后验证 Token 中是否包含 `ROLE_ADMIN`
- ✅ **Token 过期处理**：自动跳转登录页

### 2. 数据安全
- ✅ **HTTPS 传输**：生产环境必须启用 SSL
- ✅ **XSS 防护**：Element Plus 组件已内置防护
- ⚠️ **CSRF 防护**：如果需要，可以在后端添加 CSRF Token

### 3. 操作审计（未来扩展）
- 记录所有配置修改操作（操作人、操作时间、修改内容）
- 存入 `admin_operation_log` 表

## 🚧 风险与应对

### 风险 1：后端 API 问题
**风险**：现有 Admin API 可能存在 Bug 或缺失字段

**应对**：
- 开发前先用 Postman 测试所有 API
- 发现问题及时反馈后端团队修复

---

### 风险 2：权限设计不足
**风险**：所有管理员权限一样，无法细分（如只读管理员 vs 超级管理员）

**应对**：
- 第一版先实现单一管理员角色
- 未来扩展：后端增加 `ROLE_SUPER_ADMIN`、`ROLE_OPERATOR` 等细分角色

---

### 风险 3：并发修改冲突
**风险**：多个管理员同时修改同一配置

**应对**：
- 第一版不处理（管理员较少，冲突概率低）
- 未来扩展：后端增加乐观锁（version 字段）
