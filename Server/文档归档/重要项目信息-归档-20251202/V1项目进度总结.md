## 💡 核心设计亮点

### 1. 后端计算模式（GPT建议）
**问题**: 褪色公式如果前后端不同步，会导致"面板显示A，实际运行B"

**解决方案**:
- ✅ 采用后端计算方案
- ✅ 前端只负责输入参数、调用接口、绘制图表
- ✅ 单一真相来源，公式升级无需改前端

**优势**:
- 避免前后端公式不一致
- 复杂公式无需翻译成JavaScript
- 未来公式升级，前端自动同步

### 2. 审计日志系统（GPT建议）
**问题**: 无法追踪"谁、什么时候、改了什么配置"

**解决方案**:
- ✅ 创建 `admin_operation_log` 表
- ✅ 记录 before/after 完整值（JSON格式）
- ✅ 在所有 save/update/delete 接口中自动记录

**优势**:
- 排查问题（"褪色规则突然变了，谁改的？"）
- 支持回滚（查看历史值，恢复旧配置）
- 审计追踪（符合生产环境规范）

### 3. 结构化表单
**问题**: 自由JSON输入容易出错，格式错误会"一行打死系统"

**解决方案**:
- ✅ 使用 Element Plus 表单组件
- ✅ 字段分离输入（避免手动编写JSON）
- ✅ 表单验证（必填字段、数值范围）

**优势**:
- 降低出错率
- 提升可用性（普通运营也能操作）
- 保持"简洁好用"的设计原则

**Nginx配置**（已准备好）:
```nginx
server {
    listen 443 ssl;
    server_name onettoo.com;

    ssl_certificate /path/to/cert.pem;
    ssl_certificate_key /path/to/key.pem;

    # 管理后台静态文件
    location /admin {
        alias /var/www/admin-panel/dist;
        try_files $uri $uri/ /admin/index.html;
        index index.html;
    }

    # 后端 API 反向代理
    location /api/ {
        proxy_pass http://localhost:8085;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```
